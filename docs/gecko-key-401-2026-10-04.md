# Gecko alt host 401 追查（2026-10-04）：key 形狀唔對，唔係 plan／header 錯

> 相關：`docs/gecko-429.md`（keyless 429 同 alt host 嘅由來）、
> `docs/gecko-key-launch-chain-2026-09-28.md`（key 上線 + 5 分鐘 cadence）。
> 新工具：`/debug/gecko-key`（唯讀；`?bust=1&seq=1&only=<variant>&mint=<addr>`）。

## 一、問題形狀

`/health.summary.gecko` 一直見到兩款拒絕：主 host 牆式 429
（`http429`／`consecutive429` 一齊升，例：6／6），alt host 又會 401
（`altLastStatus 401`、`altFailures 1`），而 `geo` 大部份 tick 0，只偶爾出 20。

`/health` 分唔清「key 型別／plan 同 header 唔配」 vs「key 本身唔有效」——
兩者都只係一個拒絕。所以加咗 `/debug/gecko-key`：用**部署緊嘅 key**（唔會 echo 出嚟）
重播所有 Host × Header 組合，`?bust=1` 加 unique `cb=` 令每個讀數都係 **origin 答案**
（唔 bust 嘅話全部係 `cf-cache-status: HIT`，keyed／keyless 都一樣 200 —
cache 係 auth 之前就答，所以「cache 200」證明唔到任何關於 key 嘅事）。

## 二、量度

### 2.1 沙盒（乾淨主機、keyless、cache-bust）— path 政策

| host | `new_pools` | `tokens/SOL` | `trending_pools` | 結論 |
|---|---|---|---|---|
| `api.coingecko.com/api/v3/onchain`（alt public） | **401** `Requests without API key are not allowed for this endpoint` | **401** | **401** | 成個 host 都**要 key** |
| `api.geckoterminal.com/api/v2`（主） | 200（`s-maxage=60`） | 404（path 存在，SOL 唔係 pool token） | 200 | keyless 照服務（限 IP） |
| `pro-api.coingecko.com/api/v3/onchain` | **401** `API Key Missing`（10002） | — | — | 只要 Pro key |

### 2.2 `/debug/gecko-key`（部署 Worker、真 key、`?bust=1&seq=1`）

部署配置：`keyed true`、`plan demo`、header `x-cg-demo-api-key`。

| host | variant（header） | status | cache | 回應 |
|---|---|---|---|---|
| primary | demo key（configured） | **429** | — | `You've exceeded the Rate Limit…` |
| primary | keyless | **429** | — | 同上（**key 唔改變主 host 嘅 IP 429**） |
| alt-public | demo key（configured） | **401** | MISS | `10002 API Key Missing. Please make sure you're using the right authentication method. For Pro API…` |
| alt-public | keyless | **429** | BYPASS | same rate-limit shape |
| alt-pro | pro header（configured key） | **401** | — | `10002 API Key Missing` |
| alt-pro | keyless | **401** | — | `10002 API Key Missing` |

429，所以個牆唔係自己嘅 burst 造成。）

## 三、結論（量度支持）

1. **plan／header 配置係啱嘅**：`plan=demo` + `x-cg-demo-api-key` 正正係
   CoinGecko public host 收嘅配對；repo 亦冇任何地方設定 `COINGECKO_API_PLAN`，
   所以 demo 係預期值。（如果有 dashboard var 蓋過咗，唔會影響）
2. **401 嘅真正原因係 key 唔被接受**：`api.coingecko.com/api/v3/onchain` 係 key-gated
   （keyless → 401 origin），而**帶住呢個 key 都係同一個 401**（`API Key Missing`）；
   pro host 亦一樣拒收。即係 CoinGecko 唔認得呢條 key，唔係「用錯 header」。
3. **形狀唔對**：CoinGecko API key（demo 定 pro）都係 `CG-` 開頭嘅長 key；
   依家嗰條係 **24 字、冇 `CG-`、只有 alnum／dash** —— 唔似 CoinGecko key
   （可能貼錯咗第個服務嘅 key，或者一條截短咗嘅值）。key 被 trim 過、無空白、
   無引號，所以唔係「secret 有換行／引號」嗰類整壞。
4. **主 host 嘅 429 同 key 無關**：keyed 同 keyless 主 host 都係同一個 429 ——
   就算 key 有效，主 host 都要等 shared egress IP 嘅窗口；alt host 先係 key 真正幫得到嘅位。
5. **geo 為何仍然偶爾出 20**：CoinGecko publish `s-maxage=60`，edge cache HIT 嘅
   200 唔查 key，所以偶爾有 20 個 pool 落到（`altOk`／`ok` 大多數係 HIT），
   但 origin 一問就 401／429 → 大部分 tick 0。

## 五、同步落地嘅一個真 gap：mirror 要跟 plan

`geckoterminal.ts` 原本 hardcode `GECKO_ALT_BASE_URL`（public host）做 fallback
mirror。public host 只收 demo header、pro host 只收 pro header，所以
`plan=pro` 嘅部署（header 反轉成 `x-cg-pro-api-key`）就算有**有效** key，
fallback 都永遠 401 —— 而 `/health` 只会顯示「被拒」。

本次加咗 `GECKO_PRO_ALT_BASE_URL` + 純函數 `geckoAltBaseUrl(plan)`，client 用佢揀
mirror；unit test 釘住：`demo → api.coingecko.com/api/v3/onchain`、
`pro → pro-api.coingecko.com/api/v3/onchain`，而且 pro client 喺暫停時真的問 pro host
同帶 pro header。

## 六、工具（`/debug/gecko-key`）

| query | 作用 |
|---|---|
| `?bust=1` | 加 unique `cb=` → 每條讀數都係 origin（唔 bust = cache HIT，證明唔到 key） |
| `?seq=1` | 逐個隔 1.2s 發，排除「自己 burst 造成 429」嘅歧義 |
| `?only=demo,param-demo` | 只跑指定 variant（`configured`／`demo`／`pro`／`keyless`／`param-demo`／`param-pro`） |
| `?mint=<addr>` | 加埋 post-push snapshot path（tracker 嘅 leg） |
| 回應 | `keyShape`（boolean／長度）＋ 每個 host × variant 嘅 status／cache／count／`errorMessage` |
